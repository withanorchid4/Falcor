官方 Cornell：DDGI 与稳定 Path Tracer 对比（2026-11-16）

在 NVIDIA RTXGI-DDGI 1.3.7 Test Harness 内切换两种渲染模式，保持相机、场景、灯光和后处理一致。官方 DDGI 的整体结果接近 PT，但柱体暗面明显偏暗。这次只操作官方程序，没有修改渲染代码，也没有将 Falcor 图像混入比较。

比较的是直接光加间接光的完整画面。官方 Path Tracer 的现有界面没有与 DDGI 对应的仅间接光输出，因此没有把 DDGI 的仅间接光与 PT 完整光照混比。

| 设置 | 数值 |
|---|---|
| 分辨率 | 1920×1080 |
| 相机 | 位置约 (-0.09, 1.05, 3.79)，yaw 2.33°，pitch 2.00°，垂直 FOV 45° |
| 灯光 | 顶部白色点光源 (0, 1.9, 0)，Power 1，Radius 4；方向光 Power 0 |
| DDGI | 9×9×9，共 729 个 probe；256 rays/probe；relocation、classification 开启 |
| PT | 每帧每像素 1 条路径，最多 20 次反弹；抗锯齿和渐进累积开启 |
| 后处理 | Exposure +1 stop、ACES、Gamma 开启；额外 RTAO 关闭 |
| 显示抖动 | 两侧均关闭 Color Banding Reduction，避免它的逐帧噪声干扰收敛测量 |

先通过实际相机移动清空 PT 累积，再固定相机，观察到累积帧数超过 41,000 后保存最终参考。最终两张 PT 图相隔约 67 秒：房间区域的平均显示亮度只变化 0.00022%，RGB 平均绝对变化为 0.044/255，相对 RGB L1 为 0.047%。这说明当前图像已足够稳定，下面的 DDGI 差异远大于这段时间内 PT 的变化。

随后在同一相机位置切回 DDGI，重新启用 DDGI、等待更新后截图。统计排除房间外背景，房间掩码和各表面取样矩形保存在分析脚本中。

| 测量区域 | DDGI 相对 PT 的平均显示亮度变化 |
|---|---:|
| 房间整体 | -1.54% |
| 后墙取样区域 | +0.06% |
| 高柱正面取样区域 | -6.46% |
| 矮柱暗正面取样区域 | -24.60% |
| 前景地板取样区域 | -0.89% |
| 红墙取样区域 | -1.80% |
| 绿墙取样区域 | -0.81% |

房间整体 RGB 平均绝对误差为 2.31/255，相对 RGB L1 为 2.49%。这些是经过曝光、ACES 和 Gamma 的最终 8-bit 截图统计，不代表线性 GI 能量误差。矮柱本来很暗，其 24.6% 的相对亮度差对应约 2.69/255 的绝对显示亮度差；整体平均值也会被直接光占比较大的区域稀释。

视觉上，两者的大面积色彩与照明分布接近；DDGI 高柱正面更暗，矮柱暗面和地面接触附近的亮度过渡也不同。PT 开启了像素抗锯齿，DDGI 的几何边缘更锯齿化，这部分也计入整体像素误差。

DDGI 用有限探针存储、过滤并插值间接光，PT 则逐像素累积多次反弹路径，存在局部偏差符合两种方法的差别。此次测量没有把探针插值、可见性、bias、材质编码等误差来源逐项分离，因此不能把全部偏差归因于某一个 DDGI 参数。官方 PT 自身也设置了最大反弹数和低吞吐量终止，作为该示例的稳定参考使用。

结果说明：官方示例的 DDGI 本身就不会与稳定 PT 完全一致。验证 Falcor 接入时，应先与相同配置的官方 DDGI 对齐，再单独讨论两者相对 PT 的近似误差。

原始截图、对比图、分析脚本及完整统计保存在 `build/official-ddgi/ddgi-vs-pt-20261116/`：`ddgi-total.png`、`pt-A.png`、`pt-B.png`、`comparison.png`、`analyze.py`、`metrics.json`。执行 `python build/official-ddgi/ddgi-vs-pt-20261116/analyze.py` 可重新生成统计和对比图。
