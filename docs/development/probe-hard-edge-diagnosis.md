# Probe 墙面硬边定位（2026-09-24）

## 契约

仅定位，不改生产 GI 算法或缓存。输入是已逐像素复现的快照 `20260924-021543-642825`。
使用独立 headless Mogwai；复制其 shader 到独立运行目录后注入只读诊断分支，不修改生产 shader。
复用原 `probeCell`、`cornerWeight`、`distanceMoments` 和 SH 计算，避免 CPU 另实现导致误判。

## 步骤

1. 原图复现并验证 HDR/显示误差为零。
2. 在同一相机全分辨率输出世界位置、法线、albedo，以及 8 个邻居各自的：
   - 归一化权重、未归一化权重、可见性；
   - 三线性、朝向、总权重；
   - mean、原始方差、查询距离；
   - Probe ID、八面体 UV；
   - 未加权 SH irradiance、加权贡献；
   - 真实射线命中距离、可见性（诊断参考）。
3. 数据输出读取线性浮点 EXR，所有可视化在 CPU 端明确标尺，不经过 ToneMapper。
4. 比较标记区域中的图像和相邻像素，跟踪固定 Probe ID（邻居槽位会随 cell 改变）。
5. 检查 albedo/normal、权重和、方差基础值、距离减 mean、归一化放大、SH 项等竞争解释。
6. 只做明确记录的单因素对照，保留原快照；报告证据与未确定项，不把相关性写成因果。

## 验证

诊断分支关闭时与基准逐像素比较；8 个贡献求和应能重建生产 irradiance。
所有数据须有限。记录相机、缓存、运行文件哈希、诊断 shader 和像素坐标。
诊断入口仅在隔离运行目录有效，不为运行时添加开销。

## 定位结果

输入使用 angular / 14×14 / 2048 rays / exponent 50，Bilinear，visibilityPower=3，varianceBase=1e-6，normalBias=.05，viewBias=0。

成功数据目录：`build/probe-hard-edge-diagnosis-03/`；`analysis/` 包含 8 邻居概览图、固定 ID 分解图、相邻像素 JSON、四 texel 读取值和因素对照。前两次目录是截图接口排查留下的失败运行，不作为结论依据。

- 诊断分支关闭时 HDR 与原快照最大误差为 0。
- 59 张线性 RGB 浮点诊断输出全部有限；8 项贡献重建墙面 HDR 最大误差 1.51e-5。
- 611714 个墙面像素的未归一化权重和在 .11556.. .94286，远大于归一化分母下限 1e-4。
- 三处选出的相邻像素法线均为 (0,0,-1)，albedo 均为 (.3000488,.3000488,.3000488)。三线性、朝向权重及实际 Probe ID 稳定；无 SH 值跳变。

三处实际射线在两像素均 blocked，且 d>mean 在两侧均成立。因此不是这批样本的 d/mean 分支翻转，也不是 0/0、基础方差或总权重下限触发。

以左侧 375 为例：

- d=.427502→.427336，mean=.411297→.410083，hit=.400327→.400171。
- SH irradiance=(3.74782,5.01107,6.56061)，邻近可见 Probe 327 为 (.29113,.30811,.27840)。较小的漏光权重也会贡献显著能量。
- 仅把 A 点的 d 换成 B：V=.65554；仅换 mean：.61126；仅换 variance：.31544；全部换为 B：.27832。这些有限变化对照不可线性相加，但表明方差变化影响最大，mean 也有贡献。
- 距离最大值 D=2.087858；1e-6 基础方差换算到世界单位是 4.35915e-6，远小于这两个 raw variance。
- 缓存 texel (12,12) 方差=.054402，(12,13)=.00055727。前者的双线性权重从约1.954%降为0，后者权重从95.844%升至98.214%；只占约2%的高方差 texel 足以显著抬升混合方差。
- 四 texel 的 CPU 重建与 GPU mean/variance 均误差 <1e-5。混合后的方差主要来自 texel 自身方差，另有各 texel 均值差异贡献；不是简单插值 variance。

采样关系是连续的，但双线性纹理的斜率会在 texel 中心网格处改变，叠加 Chebyshev 的非线性和 power=3，产生屏幕上陡峭、带折线形状的可见性变化。这批证据不能推出“只要提高分辨率就一定修好”，也未进一步重新追踪导致缓存内高方差的每条烘焙射线。

## 因果对照

仅覆盖 `visibilityMode=rayTraced`，用生产运行环境重放相同缓存，输出：
`build/probe-issues/20260924-021543-642825/runs/20260924-023100-9a017f/`。

相机和缓存哈希一致。三处标记硬边消失；同一对像素的线性亮度差分别从 .0036265 / .0081069 / .0016810 降至 .00001445 / .000000418 / .00001797。墙面整体更暗，因为错误贡献被遮挡 Probe 的光照被去掉了；该图是可见性参考，不代表完整照明 ground truth 或最终修复。

结论：当前标记硬边的主要链路是 **缓存相邻方向的距离矩差异 → 插值方差和 mean 快速变化 → Chebyshev 可见性变化 → 明亮但实际被遮挡的 Probe 权重/能量变化**。有贡献的邻居归一化也会随之变化，但未发现其本身的异常分支。原算法和缓存均未修改。

```powershell
python tests/probe_gi/hard_edge_diagnose.py F:/build/probe-issues/20260924-021543-642825 F:/build/new-probe-diagnosis

```

诊断 shader 只在独立目录中利用现有 debug 开关编码变量组，不改正式 DLL 接口。EXR 在进程结束、后台写入完成后读取，避免活跃进程中同时读写 FreeImage 文件。`hard_edge_analyze.py` 的标记区域和固定 ID 是本案例专用；换场景应重新选取区域和 Probe ID。
