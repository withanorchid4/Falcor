# 传统光照探针第一版：开发契约

状态：第一版已实现，Cornell/Vulkan 验收通过。实现前建立本文；后续范围、公式或接口变化必须先修改本文，并在末尾记载原因。

## 1. 目标和边界

实现 `TraditionalProbeGI` RenderPass：静态场景中烘焙规则网格的 L2 RGB SH（9 项），保存文件；另一次进程只加载文件，实时使用八邻域三线性插值照亮漫反射表面。保留 VBufferRT 相机可见性、解析光源直接光和表面自发光。默认显示不使用无限累积。

第一版是传统预计算探针，不含 DDGI、可见性矩、自动重定位、动态更新、镜面间接反射、体积介质与透射正确性保证。低阶 SH 和无可见性插值可能漏光或产生负值，重建辐照度最终钳制为非负。探针处于实体内会降低质量；允许手动设置网格范围。自动范围只是场景包围盒向内缩 5% 的起点。

## 2. 光照语义与公式

世界坐标方向 d 从探针指向场景。每个探针均匀球面随机采样，追踪入射辐亮度 L(d)，投影：`c[k] = (4π/N) Σ L(d_i)Y[k](d_i)`。采样 PDF 为 `1/(4π)`，不得额外乘余弦。

SH 顺序固定为 `[1, y, z, x, xy, yz, 3z²-1, xz, x²-y²]`，归一化系数依次为 `[0.2820947918, 0.4886025119, 0.4886025119, 0.4886025119, 1.0925484306, 1.0925484306, 0.3153915653, 1.0925484306, 0.5462742153]`。文件保存平均后的入射辐亮度 SH，GPU 烘焙期间保存未除 N 的投影和。

实时先插值 SH，在世界空间着色法线 n 上计算 `E(n) = Σ A[l] c[k]Y[k](n)`，余弦卷积系数为 `[π, 2π/3, π/4]`，然后输出 `diffuseReflectionAlbedo × max(E,0)/π`。只在这里卷积与乘表面漫反射率。

探针路径复用 MinimalPathTracer 的 BSDF 采样、材质和阴影处理。探针第一段直接看到的自发光/环境计入探针，因此实时不另做自发光面/环境的直接光采样；解析点光/方向光没有可命中的发光几何，实时显式计算其直接光，探针中只包含它们经表面反射的贡献。屏幕可见表面自身的 emission 另加，背景按场景环境背景设置显示。由此避免重复计算。

`maxBounces` 表示探针射线命中后允许反射继续的次数：0 仍能记录首次命中的自发光或环境；>=1 在首次命中处加入解析光源贡献并继续散射，沿用 MinimalPathTracer 的深度语义。默认 3。

## 3. 实现结构

- `Source/RenderPasses/TraditionalProbeGI/TraditionalProbeGI.{h,cpp}`：插件、设置、状态机、文件读写、绑定。
- `TraditionalProbeGI.rt.slang`：从 MinimalPathTracer 派生并保留许可证；复用求交/材质代码，以探针烘焙和屏幕采样两个运行阶段替换相机路径追踪入口。
- `ProbeSH.slang`：共享 SH 基函数和余弦卷积常量。
- 插件 CMake 和父 CMake 注册；`scripts/TraditionalProbeGI.py`：交互图。
- `scripts/TraditionalProbeGIValidation.py`：由环境变量选择 bake/load/对照模式，固定场景，离线渲染、捕获并退出。
- `tests/probe_gi/`：SH 数学、缓存格式与渲染输出检查工具；不引入新的第三方依赖。
- `Run-ProbeGI.ps1` / `.cmd`：复用本地 F: 映射约定，支持烘焙或只读加载。

单个插件内部包含两个阶段；不使用新全局框架或改动现有 PathTracer。每个探针由一个 RayGen invocation 独占写 9 个 float4，分批串行采样，避免浮点原子。烘焙批次之间和烘焙到显示之间明确 UAV 屏障。烘焙完成后停止所有探针采样派发；实时阶段只读取 SH，解析光源可发阴影射线。

## 4. 参数与状态

属性：`mode`（manual/bake/load/auto，交互默认 manual），`cacheFile`（空值时按场景自动命名），`sceneRevision`（用户控制的外部资产版本字符串），`gridCounts`（默认 8×6×8，每轴 2..32），可选成对 `gridMin/gridMax`，`samplesPerProbe`（默认 2048，1..65536），`samplesPerFrame`（默认 16，1..64），`maxBounces`（默认 3，0..8），`intensity`（默认 1，非负），`enableProbes`（默认 true），`showProbeOnly`（默认 false），`normalBias`（默认 0.05，网格最小间距的比例）。交互扩展行为以第 8 节为准；原自动化模式保持兼容。

输入：`vbuffer`，可选 `viewW`；输出：`color`（RGBA32Float）与 `probeLighting`（RGBA32Float，漫反射探针贡献）。grid 外采样钳制到边界探针，日志和文档说明不具备无限空间覆盖能力。

状态：未初始化 → Waiting（manual）或尝试加载/开始烘焙（自动模式）→ Baking → 保存并 Ready。未完成探针不作为最终结果显示；默认提供明确标注的未烘焙材质预览，关闭后仅显示直接解析光/自发光。完成后发 RenderOptionsChanged 刷新标志。相机和分辨率变化不触发重烘焙。UI 参数与操作见第 8 节。

manual 等待按钮；bake 总是重新计算；命令行 load 对缺失、不匹配或损坏文件报错，不可偷偷烘焙；auto 尝试加载，失败记录原因后烘焙。场景载入时重建状态。交互中检测几何/灯光/材质/环境等变化后让数据失效，返回 Waiting 等待手动 Bake；不在动画中自动连续更新。首次帧的初始化 flags 不应误判为用户修改。不得因相机变化让探针失效。

## 5. 缓存契约

使用可检查的文本格式，首行为 `FALCOR_PROBE_SH 1`。元数据记录场景规范路径、主场景文件修改时间、sceneRevision、网格数量和范围、样本数、反弹次数；隐含本版 SH 顺序及世界空间/线性 RGB 约定。随后按 `x + nx*(y + ny*z)` 顺序保存每探针 9 组 RGB，float 按 max_digits10 写出。

加载先验证完整元数据、数量上限、系数有限性、文件是否截断或有多余数据；仅验证成功才上传 GPU。不把 mtime 当作全部资产哈希：外部模型、贴图或灯光脚本变化后必须改 sceneRevision 或强制 bake。默认文件放在忽略的 `build/probes/` 下。保存错误必须报告，不能显示为成功。读回只发生于烘焙完成时，不出现在正常实时帧。

## 8. 交互烘焙扩展（先设计，后实现）

用户需求：在 Mogwai 内切换场景，手动触发 Bake，并调整烘焙参数。只修改 TraditionalProbeGI 插件、图脚本、启动器、文档与测试；继续使用 Mogwai 现成的 File → Load Scene / Ctrl+Shift+O，核心框架、渲染图接口和 SH 算法不变。

### 8.1 操作与状态

- 交互启动默认 `manual`。载入或切换场景后处于 Waiting，既不自动加载，也不自动烘焙。UI 明确提示点击 Bake 或 Load matching cache。
- 新场景丢弃前一场景的 GPU 探针，重置进度；网格密度与样本等参数保留，换场景后范围回到自动包围盒，避免沿用上个场景的坐标。初次启动仍允许脚本指定范围。
- Bake 使用当前有效参数，从零开始并在完成后保存；Cancel bake 停止并丢弃未完成结果，返回 Waiting。不得把部分采样结果当作完成缓存保存。
- 面板可编辑：每轴探针数量、自动/手动范围与 min/max、每探针样本数、每帧样本数、反弹次数、sceneRevision。显示总探针数、估计总路径数、当前进度与缓存路径。
- 影响烘焙结果的参数一旦更改，当前结果立即失效，停止正在进行的 Bake，等待用户再次点击；每帧样本数仅控制批次大小，可在烘焙中调整，保留已完成样本。强度、normalBias、开关和只看探针贡献只影响显示，无需重烘焙。
- min/max 编辑过程允许临时非法范围；面板显示错误并拒绝 Bake/Load，程序不退出，不派发非法网格，也不使用旧结果照明。
- Waiting/Baking 默认显示表面漫反射颜色预览与可见自发光，并按法线方向添加简单明暗以区分同色几何；标注为 Unbaked material preview。这不是烘焙照明，不含阴影。可关闭预览恢复直接光显示。Ready 以及 Ready 下关闭探针的对照行为保持不变。

### 8.2 缓存与修改场景

- 默认缓存名使用场景文件名加规范路径的稳定 64 位 FNV-1a 标识，置于 `F:/build/probes/`，防止不同场景互相覆盖。路径在面板中可见；高级脚本显式传入 cacheFile 时仍使用指定文件，以兼容已有自动化测试。
- Load matching cache 只加载与当前场景和参数相符的文件；错误显示在面板，保持 Waiting，不自动 Bake、不退出。命令行 `mode=load` 保留严格失败行为。
- 同场景灯光、材质、几何等发生变化时，不再让交互程序退出：失效当前探针，必要时重建光追程序，等待手动 Bake。需重编译的几何变动通过现有场景/绑定接口处理。相机与窗口变化不让探针失效。动态场景仍需要先暂停，避免烘焙过程中不断失效。
- 缓存格式保持 v1。保存失败时保留已完成 GPU 结果并显示错误，不假称已成功保存。

## 11. 探针诊断可视化（实现前约定）

目标：解释斑块和漏光来源，不在本次修改生产光照算法或缓存格式。所有调试功能默认关闭，关闭后正常光照与此前一致，调试设置不触发 Bake，也不写缓存。

1. Probes 面板增加 Debugging 分组：显示模式（正常、纯辐照度、材质反射率、世界法线、网格单元、越界区域），探针球、编号、网格包围盒、透视显示及球尺寸开关。可只显示选中单元的八个探针以减少遮挡。
2. 开启 Pick surface 后在视口右键选择像素（初版使用左键，第 12 节修订），将位置和法线固定在世界空间；相机移动后仍检查同一位置。背景点击清除选中点，场景切换或探针数据重置清除旧选择。提供归一化坐标脚本入口供实际 Vulkan 集成验证。
3. 显示偏移后的采样位置到实际参与三线性插值的 8 个探针的连线；显示探针编号、位置、权重、单探针对选中法线的辐照度贡献与可见性。记录网格坐标被 clamp 的情况。权重必须复用生产采样计算，遮挡不影响权重。
4. 对这 8 条连线用现有 alpha-test 阴影射线做遮挡诊断：绿色可见、红色被挡，零权重不画线。原表面到 Normal bias 偏移位置单独显示，便于识别偏移穿墙。射线端点使用小尺度 epsilon，检测为诊断用途，不声称完全可靠的探针有效性分类。
5. 探针球按其 SH 重建的方向辐照度着色；增加独立的选中探针方向球预览，支持显示辐亮度/辐照度和 SH 负值标记。未完成 Bake 时球只显示占位色，不把部分结果当成完整光照。
6. 球、连线和边界使用独立光栅叠加着色器，避免每个像素遍历全部探针；普通模式进行场景深度遮挡，透视模式可看到墙后探针。GPU 拾取只处理一个点，CPU 读回仅在主动选择或调试参数改变时发生。调试关闭时不执行拾取或绘制。
7. 修改局限于 TraditionalProbeGI 插件、着色器、使用文档及集成验证脚本，不改变 Mogwai 主框架。先完成此约定，再实施；任何必要设计调整先更新本节。

验证：Windows Release 构建与 Vulkan 实际着色器执行；无烘焙/烘焙后显示、选择及空背景、权重和为 1、八探针 ID/范围、遮挡信息、移动相机保持世界锚点、debug 开关不改变正常 HDR 输出/缓存、场景切换清理状态；保存图像并检查可视化。UI 鼠标操作未实际验证时明确说明。

## 12. 右键选点与相机事件隔离（实现前约定）
